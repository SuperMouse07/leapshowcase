## 1. 采用的方式
本项目没有引入任何第三方配置库（如 dotenv、config、conf），而是采用 Node.js 原生 `process.env` + 代码内联默认值的方式管理运行时配置。所有可配置项均通过环境变量注入，并在缺失时提供安全的开发默认值。

## 2. 关键文件
- `backend/server.js`：应用入口，读取 `PORT`、`JWT_SECRET` 等运行时参数并启动 Express。
- `backend/db.js`：数据库抽象层，根据 `DATABASE_URL` / `PGHOST` / `PGSSL` 动态切换 PostgreSQL 或 SQLite，并处理 SSL 策略。
- `Dockerfile`：声明 `NODE_ENV=production`、`PORT=8080`，并通过 `HEALTHCHECK` 暴露健康检查端点。
- `.gitignore`：显式忽略 `.env` 与 `.env.*`，防止敏感配置入库。

## 3. 架构与设计约定
### 3.1 配置来源分层
| 层级 | 变量名 | 用途 | 默认值/行为 |
|---|---|---|---|
| 端口 | `PORT` | 监听端口 | 本地 `3000`；Docker 中由 Zeabur 注入 `8080` |
| 密钥 | `JWT_SECRET` | JWT 签名密钥 | 开发默认 `'leapchess-dev-secret-change-me'` |
| 数据库选择 | `DATABASE_URL` 或 `PGHOST` | 是否启用 PostgreSQL | 未设置则回退到 `backend/data/leapchess.db` 的 SQLite（WASM） |
| 数据库连接 | `DATABASE_URL` | PostgreSQL 连接串 | 支持在 URL 中携带 `sslmode=require|verify-ca|verify-full` |
| SSL 开关 | `PGSSL` | 强制开启 pg SSL | 仅接受 `true/1/on`（不区分大小写） |
| 运行环境 | `NODE_ENV` | 运行模式 | Docker 镜像固定为 `production` |

### 3.2 数据库后端自动切换
`db.js` 在模块加载时即判定 `usePg = Boolean(process.env.DATABASE_URL || process.env.PGHOST)`，随后 `connect()` 返回统一接口 `{ query, run }`：
- PostgreSQL：使用 `pg` Pool，内部将 `?` 占位符转换为 `$1/$2...`。
- SQLite：使用 `sql.js`（纯 WASM），每次写操作后调用 `persist()` 将内存数据库快照落盘至 `backend/data/leapchess.db`。
- `initSchema()` 针对两种后端分别执行建表语句，对外屏蔽差异。

### 3.3 单服务静态托管
当 `../frontend` 目录存在时，Express 会将其作为静态资源托管，并将非 `/api/*` 路由重定向到 `index.html`，实现前后端单体部署（Zeabur 一键部署场景）。

## 4. 约定与约束
- **禁止硬编码生产凭据**：`.gitignore` 明确排除 `.env` 和 `.env.*`，要求敏感信息通过部署平台（Zeabur）的环境变量注入。
- **生产必须使用 PostgreSQL**：启动时会输出警告提示“Zeabur 文件系统无状态，重新部署会丢失 SQLite 数据”，引导在生产环境配置 `DATABASE_URL`。
- **JWT 密钥必须覆盖**：`JWT_SECRET` 的开发默认值带有 `-change-me` 后缀，意在提醒部署时必须替换。
- **端口遵循平台约定**：Dockerfile 声明 `PORT=8080` 并与 Zeabur 默认端口一致，便于路由发现。
- **配置读取时机**：所有 `process.env` 在模块顶层立即读取（而非懒加载），因此环境变量必须在进程启动前就绪。
- **无配置文件格式**：项目不使用 YAML/TOML/JSON 配置文件，也不使用 `dotenv` 等库，所有配置均以环境变量形式提供。
- **健康检查端点**：`/api/health` 返回 `{ status, db, time }`，供容器编排探测服务可用性。

## 5. 总结
该项目的配置系统极其轻量：零依赖、无配置文件、全部通过 `process.env` 注入，配合内联默认值保证本地开发开箱即用，同时通过 `.gitignore` 和环境变量机制保障生产安全。数据库后端的选择是唯一的“配置分支点”，由 `DATABASE_URL` / `PGHOST` 决定，体现了“开发用 SQLite、生产用 PostgreSQL”的清晰约定。

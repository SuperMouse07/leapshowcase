# ADR-0004 · 业务范围收敛：标准产品为主，商品标签区分促销/定制

- **状态**：已采纳（Accepted）
- **日期**：2026-10-12
- **相关文档**：[proposal.md](../proposal.md)、[design.md](../design.md)、[tasks.md](../tasks.md)、[contracts/README.md](../contracts/README.md)、[ADR-0001](./ADR-0001-spec-workflow-and-constraints.md)

## 背景（Context）

ADR-0001 将新站定位为“B2B 定制礼品采购”，此后 proposal/design/tasks 均按“整站即定制礼品站”展开，并计划“用定制礼品分类替换旧国际象棋固定分类”。

用户于 2026-10-12 澄清真实业务范围：礼品定制只是产品的一部分，主体是棋盘等标准产品的销售，应以 LeapShop/LeapChess 生产基线的标准产品目录为主进行开发，删除规格里“纯定制站”的定位。进一步澄清：定制不宜做成单独字段，而应与“降价促销”等一样，作为**商品标签（badge）**统一处理——一个商品可挂多个标签，前台展示、后台配置。

## 决策（Decision）

1. **主线重定位**：新站以标准产品（棋盘等）展示与采购为主线，直接继承 LeapShop 现有商品模型与分类，不再整体替换为定制礼品分类。
2. **标签机制取代定制专用字段**：`products` 新增 `tags`（字符串数组，默认 `[]`），承载可展示的商品标签，例如“降价促销”“可支持定制”。定制品即“带有‘可支持定制’标签的商品”，不再引入 `is_customizable` 之类的专用布尔字段。
3. **前台展示 + 后台配置**：标签在前台商品卡片与详情页以徽标呈现；在后台商品编辑处按商品增删。可选地在 `settings` 维护受控标签词表，以统一文案与样式（非首版必需）。
4. **最小化改动**：沿用现有 JSON 字段落库方式（与 `images`/`variants` 一致），不新增标签表、不引入独立标签管理模块；若未来需要标签的多语言、颜色/图标样式或统计，须另立 ADR 论证（遵守 C4）。
5. **删除纯定制表述**：proposal/design/tasks/contracts 中“定制礼品采购站”“用定制礼品分类替换旧分类”“定制礼品分类与商品模型调整”等表述按本 ADR 改写。
6. **交易语义暂不变**：本轮不改变既有 B2B 询单/购物清单语义；“降价促销”标签仅为展示语义，是否引入在线下单/价格规则属独立决策，不在本 ADR 范围内。

## 影响（Consequences）

- ✅ 正面：定位与真实业务一致；用一套通用标签机制同时满足“促销”“定制”等多种展示需求，避免为每种属性加专用字段；复用已验证的标准产品目录，改动面小。
- ⚠️ 代价：`tags` 是新增字段，需通过版本化迁移引入，并在契约冻结时写入 `openapi.yaml`；前台需新增徽标渲染、后台需新增标签编辑控件。
- 关联：ADR-0001 中“B2B 定制礼品采购”的站点定位由本 ADR 取代；proposal Q3、tasks B3/E3、design D3 的验收方向随之调整。

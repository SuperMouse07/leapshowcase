# ADR-0005 · 后台访问入口、主账号/子账号权限模型与操作审计增强

- **状态**：已采纳（Accepted）
- **日期**：2026-10-12
- **相关文档**：[proposal.md](../proposal.md)、[design.md](../design.md)、[tasks.md](../tasks.md)、[contracts/README.md](../contracts/README.md)、[ADR-0003](./ADR-0003-production-baseline-realignment.md)

## 背景（Context）

旧生产基线 `../LeapShop@0476933` 的后台访问与权限现状：

- 后台 `admin.html` 无可见入口，通过“2 秒内连敲 5 次空格”的隐藏手势或直接 URL 进入；未登录跳 `login.html`，`demo` 被拒，`admin`/`tester` 进入后台。
- 角色固定为 `admin/tester/demo` 三种，无按账号配置的细粒度权限。
- `login.html` 明文展示种子账号密码（`P001/123456` 等），属 P0 安全隐患（proposal K3 / design C5）。
- `activity_logs` 已记录登录、浏览、加购与商品/轮播/设置变更摘要，但不含登录 IP 与会话时长。

用户于 2026-10-12 确认新的访问与权限需求，需据此调整规格。

## 决策（Decision）

1. **访问入口**：移除空格隐藏手势；后台仅通过直接输入 URL `/admin.html` 进入，前台导航不展示入口、不提供公开跳转链接，做到“仅已知路径可进入”。此项了结 design D9 中“后台入口”部分（主推款机制仍另议）。
2. **登录信息简化**：登录/注册仅收集用户名与密码，不绑定手机号等额外信息。预置主账号 `P001`（初始密码 `123456`），首次登录后自动初始化基础环境。
   - **与 P0 安全基线的调和**：`P001/123456` 仅作为首次启动的引导凭据，**不在登录页展示**，且首次登录**强制改密**并完成初始化；生产环境仍遵守 C5/C6（缺 `JWT_SECRET` 拒绝启动、文档不含真实凭据、不继承公开默认密码缺陷）。
3. **主账号/子账号体系**：
   - 主账号 `P001` 拥有最高权限，可访问全部功能模块，并**独占**后台“子账号管理”界面，用于创建、配置、管理子账号（各自独立用户名/密码）。
   - 子账号仅能执行被授权的具体任务（如商品编辑、轮播图管理、全站设置等），**默认仅开放商品 CRUD**，且**不能访问账号管理功能**。
   - 权限以“权限矩阵”形式在后台按子账号配置（能力项如 `products:write`、`slides:write`、`settings:write`）。
   - 与旧模型映射：主账号 ≈ 原 `admin`；子账号是对原 `tester`/`demo` 的泛化——由固定角色改为按账号授权的能力集合。
4. **操作审计增强**：审计日志需落库并支持按时间/用户筛选查询，覆盖：
   - 登录事件：登录时间、来源 IP、会话时长（由登录与登出/最后活动时间推导，轻量实现，不引入独立会话服务）；
   - 商品操作：新增/更新/删除的时间点与操作人；
   - 其他管理操作：轮播图调整、全站设置修改等，含操作人与变更摘要。
5. **C1 例外登记**：主账号/子账号权限矩阵与审计增强属超出旧固定三角色的新增能力，按 C1 登记为已批准的明确例外后，方可设计与实现。

## 影响（Consequences）

- ✅ 正面：入口更可控、登录信息最小化；权限从固定三角色升级为可配置矩阵，满足分权与最小权限；审计满足追责与合规查询。
- ⚠️ 代价：`users` 需扩展账号类型/权限/首登改密标记等字段，`activity_logs` 需扩展 IP 与会话时长；新增子账号管理与权限校验逻辑；均为新增字段/能力，须经版本化迁移引入并写入正式 `openapi.yaml`。
- 关联：了结 design D9（后台入口部分）、更新 D7/Q8（登录信息）；proposal §4.1 新增对应 P0 需求并调整 C1/C5 口径；tasks 新增 B7 决策门与 E6～E9 实施任务；contracts 增补权限/审计规划字段。
- 风险：会话时长与来源 IP 涉及个人信息，海外 B 端场景需留意隐私/合规边界（如日志保留期限），后续可在审计策略中单独明确。

## 后续细化（2026-10-12）· 审计记录与展示逻辑

用户进一步明确子账号操作审计的记录与展示逻辑，据此细化并部分调整上文决策 4：

1. **登录/退出成对记录**：主账号与子账号每次登录、退出均自动写入审计，仅截取服务器当前时间戳，无需额外手动操作。会话时长由同一用户“登录→退出”的两个时间戳推导，不单独存储。
2. **商品操作记录**：商品的新增/更新/删除均记录操作时间戳与操作人用户名（轮播图、全站设置等管理操作沿用基线审计，不因本次细化而移除）。
3. **日志内容口径收敛**：对外展示的最小必要字段为「操作类型（登录/退出/商品新增/商品更新/商品删除）、操作时间、操作人用户名」。**来源 IP 由“必记”下调为“可选/后续”**——首版不强制采集，若未来出于安全或合规需要再单独启用，以符合“直接截取当前时间即可”的最小化意图。
4. **查看权限**：审计日志查看为主账号专属能力，主账号可查看全部子账号及自身记录，并支持按时间/用户筛选；子账号默认无审计查看权限（如需开放，作为权限矩阵中的独立能力项另行授予）。
5. **持久化**：全部审计记录写入后台数据库 `activity_logs`（复用现有表，扩展 `action` 取值枚举，并在查询时联表解析操作人用户名），确保不丢失并支持后续查询与分析。

> 本细化与上文决策 4 冲突处（IP 是否必记）以本节为准。

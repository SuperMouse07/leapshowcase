## 1. 核验范围、证据等级与总体结论

### 1.1 核验范围

本次逐项核验了以下生产相关实现：

- `backend/server.js`、`db.js`、`seed.js`、`package.json`、测试脚本；
- `frontend/` 的 8 个公开页面、登录页、管理后台、共享模块与沙箱；
- `Dockerfile`、`.dockerignore`、本地素材同步工具；
- Git 分支与提交：当前旧项目 HEAD 确认为 `0476933`，与最终架构文档声明一致；
- 当前 SDD 文档：proposal、design、tasks、contracts 与 ADR。

### 1.2 证据优先级

1. `../LeapShop` 当前源码与 Git 提交；
2. `LEAPSHOP_FINAL_ARCHITECTURE.md`；
3. `GIT_HISTORY.md`；
4. `repowiki/`（历史知识库，仅作背景，不再作为当前事实源）。

### 1.3 总体结论

- 最终架构文档与 `0476933` 源码**总体高度一致**，适合作为旧生产系统的架构基线。
- 旧版 specs 对旧项目最后 5 次提交吸收不完整，仍停留在“四表、admin/customer、单主推款、商品无分页、无审计”的较早阶段；这些假设现已纠正。
- 生产系统实际包含 **5 张表**、**admin/tester/demo 三角色**、`editorOnly`、审计日志、账户管理、多主推款 `hero_products`，以及可选分页接口。
- 最终架构文档列出的高风险问题经源码复核均成立；其中路径穿越式删除风险、异步错误缺口、默认凭据/固定密钥必须先于新功能处理。
- 本仓库仍是 SDD/文档仓库，不含新站点运行代码；“已落实”均指旧生产基线已实现，不表示新 B2B 站点已完成。

## 2. 最终架构与源码逐项对比

| 架构点 | 源码核验结果 | 状态 | 对齐结论 |

## 4. 继承、修复、改造与缺口

### 4.1 直接继承（已验证资产）

单服务同源部署、双驱动 DB 抽象、幂等初始化、图片落盘+SHA1+分片+去重、settings 配置驱动、公开读/鉴权写、三层前端模块、BroadcastChannel、健康检查、存储统计、单 Dockerfile + Zeabur + Volume。

### 4.2 必须先修复的基线缺陷

| 优先级 | 问题 | 影响 | 验收方向 |
|---|---|---|---|
| **P0** | `removeUnreferenced` 路径未约束 | editor 可构造路径，在记录替换/删除时尝试删除上传目录外文件 | 只接受规范 `/uploads/<2hex>/<sha1>.<ext>`；解析后路径必须位于 `UPLOAD_DIR` 内 |
| **P0** | async 路由无统一错误边界 | 运行时异常可能挂起请求或导致进程重启 | 所有 async 路由进入统一错误中间件，返回一致 500 错误 |
| **P0** | 生产可使用固定 JWT 默认密钥与公开默认密码 | 可伪造 Token/直接登录后台 | 生产缺密钥拒绝启动；登录页移除密码；初始凭据改为部署时注入或一次性流程 |
| **P0** | `materializeVariiants` 拼写错误 | 变体更新请求必然失败 | 修正并增加回归测试 |
| **P1** | 清理引用漏算 `logo_url` | 共用哈希图片可能误删 LOGO | 引用扫描纳入所有 settings 图片引用 |
| **P1** | 冒烟脚本仍依赖 C001/customer | 测试基线给出假失败，无法保护回归 | 改为主账号/子账号权限矩阵（见 ADR-0005）并覆盖新端点 |
| **P1** | 商品分类/图片 URL 缺少集中校验 | 数据可能不可见，或进入危险清理路径 | 建立写接口输入校验层 |

|---|---|---|---|

| **P1** | 图片 multipart | base64/JSON + 80MB | 推荐，但需保持旧客户端兼容窗口或同批迁移 |
| **P2** | 异步 bcrypt | 当前同步阻塞事件循环 | 推荐执行 |

### 4.4 新站业务缺口

| 优先级 | 缺口 | 当前能力 | 处理边界 |
|---|---|---|---|
| **P0 决策** | 多语言 i18n | 单语言英文 | 与 C1 冲突；必须决定是否作为明确例外单独设计 |
| **P0 决策** | B2B 询单语义 | 本地购物车 + 文本导出 | 至少决定保留“需求清单”还是设计后端询价闭环 |
| **P1 决策** | 商品分类与标签 | 代码固定四类国际象棋/棋盘商品；无商品标签机制 | 保留现有标准产品分类；`products` 新增 `tags` 标签数组（如“降价促销”“可支持定制”），前台徽标展示、后台可增删配置 |
| **P1 决策** | 主推款语义 | 最多 4 个 Featured 商品 | 机制可复用，业务命名和选品规则待定 |
| **P1 决策** | 后台访问入口（已确认） | 2 秒 5 次空格隐藏手势 + 直接 URL | 移除隐藏手势；仅保留直接 URL `/admin.html`，前台无导航链接与公开跳转（ADR-0005） |
| **P1 决策** | 登录信息（已确认） | 登录页明文展示种子账号密码 | 仅收集用户名+密码；预置主账号 P001/123456 作首启引导，首登强制改密并初始化；登录页不再展示凭据 |
| **P1 决策** | 权限模型（已确认） | admin/tester/demo 固定三角色 | 改为主账号 P001（全权 + 独占子账号管理）+ 子账号（权限矩阵授权、默认仅商品 CRUD、不可访问账号管理）；作为 C1 例外（ADR-0005） |
| **P1 决策** | 操作审计增强（已确认） | activity_logs 已记录登录/浏览/加购/商品·轮播·设置变更（存 user_id 与变更摘要） | 登录/退出成对自动记时间戳（会话时长由二者推导）；商品增改删记时间+操作人用户名；展示字段=操作类型/时间/用户名；查看为主账号专属、可按时间/用户筛选；持久化入库；IP 首版可选（ADR-0005 后续细化） |

## 6. 非目标与过度设计边界

在约 20 并发的测试站阶段，Redis、消息队列、微服务、负载均衡、分布式追踪、复杂多租户平台仍属过度设计。CDN/对象存储只有在图片规模、全球访问或 Volume 运维成本出现实测瓶颈后再评估。

## 7. 当前结论

1. 旧生产架构可以继承，但必须以 `0476933` 源码而不是 repowiki 或旧 specs 为基线。
2. 新开发前先完成 P0 安全与稳定性修复，并恢复可信的自动化测试基线。
3. 多语言与 B2B 询单是业务缺口，不应继续被“架构改进”任务掩盖；二者需要产品决策。
4. 后台访问入口、主账号/子账号权限矩阵与审计增强已由用户确认（ADR-0005），作为 C1 例外纳入范围：移除隐藏手势仅直接 URL、登录仅用户名+密码、P001 首登初始化并强制改密。
5. TypeScript、ORM、前端框架不是当前首要矛盾；它们不能阻塞 P0 修复，也不能替代契约与测试。
6. 实施顺序与验收标准见 [tasks.md](./tasks.md)，需求边界与待确认项见 [proposal.md](./proposal.md)。

## 8. Phase 2 架构变更

本节记录 Phase 2（v0.4）在本仓库实际落地的架构调整，对应 [proposal.md](./proposal.md) §4.5、[tasks.md](./tasks.md) I1～I5 与 [ADR-0007](./record/ADR-0007-phase2-storage-and-ui-modernization.md)。

### 8.1 种子资产迁移

`backend/seed-assets/` 成为种子图片的唯一规范位置；`seed.js` 从该目录读取（原路径 `frontend/sandbox/prototype-f/assets/` 已随沙箱删除）。Docker 镜像须包含 `backend/seed-assets/` 以保证容器内可正确 seed。

### 8.2 持久化存储

Dockerfile 设置 `ENV DATA_DIR=/data` 与 `ENV UPLOAD_DIR=/data/uploads`，对齐 Zeabur Volume 在 `/data` 的挂载点。启动时验证卷可写性（写入探测失败则拒绝启动），确保数据库与上传图片持久化，重部署不丢数据。管理后台存储面板展示卷容量详情。

### 8.3 异步错误边界

引入 `wrapAsync(fn)` 包装所有 async 路由，将 rejected promise 转交终端错误中间件；终端中间件统一返回 `{ error }` JSON 与相应状态码，避免请求挂起或进程因未处理 rejection 退出（修复 K2）。

### 8.4 路径安全

`removeUnreferenced` 在删除前校验 URL 格式，仅接受正则 `/^\/uploads\/[0-9a-f]{2}\/[0-9a-f]{40}\.[a-z]+$/` 匹配的规范路径，并确认 `path.resolve` 后的绝对路径位于 `UPLOAD_DIR` 内，杜绝目录越界删除（修复 K1）。

### 8.5 JWT 密钥

生产环境（`NODE_ENV=production`）缺少显式 `JWT_SECRET` 时拒绝启动，不再回退到源码内置默认值；开发默认密钥仅在明确的开发模式下生效（修复 K3）。

### 8.6 管理后台设计令牌

`theme.css` 扩展间距比例（spacing scale）、字号比例（type scale）与表面令牌（surface tokens）；`admin.css` 改为消费这些令牌，替换硬编码的色值、间距与字号，实现视觉一致性与可维护性。

### 8.7 数据库级分页

商品列表接口在存在 `limit` 参数时改用 SQL `LIMIT/OFFSET` + `COUNT(*)`，不再全量读取后在内存 `slice`；响应结构保持向后兼容（修复 K7）。

### 8.8 批量接口

- `GET /api/stats/products-storage`：一次性返回各商品的存储统计明细，替代逐个查询；
- `PUT /api/settings/batch`：多键设置一次性更新，减少往返并保证批量写入的原子性。
